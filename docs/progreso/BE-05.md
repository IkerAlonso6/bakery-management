# BE-05 — Módulo Productos

## ✅ Implementación realizada

Se implementó el ABM (CRUD) de productos siguiendo la arquitectura en capas, uso de DTOs y normas del proyecto. Incluye:

- **Repositorio:**
  - `ProductoRepository`: Extiende `JpaRepository`. Métodos custom:
    - `findByActivoTrue()` para listar activos.
    - `existsByDescripcionAndUnidad(String, Unidad)` para controlar duplicados.
- **Servicio:**
  - `ProductoService` (interfaz) y `ProductoServiceImpl` (implementación):
    - `listarActivos()`
    - `buscarPorId(Long)`
    - `crear(ProductoRequest)`
    - `actualizar(Long, ProductoRequest)`
    - `desactivar(Long)` (baja lógica).
    - Control de negocio/manual mapping entre entidades y DTOs.
    - Excepciones claras: `RecursoNoEncontradoException`, `ReglaNegocioException`.
- **Controller:**
  - `ProductoController`:
    - Expone endpoints REST bajo `/api/productos`.
    - Valida datos de entrada (DTO request) y responde con DTO response.
- **DTOs:**
  - `ProductoRequest` (request):
    - `descripcion` (obligatorio, `@NotBlank`)
    - `unidad` (obligatorio, `@NotNull`, enum `Unidad`)
  - `ProductoResponse` (response):
    - `id` (Long)
    - `descripcion` (String)
    - `unidad` (enum)
    - `activo` (boolean)

## 📑 Endpoints implementados

- **GET `/api/productos`**
  - Listar productos activos. Respuesta: `List<ProductoResponse>`

- **POST `/api/productos`**
  - Crear producto. Request: `ProductoRequest` → Response: `ProductoResponse`

- **PUT `/api/productos/{id}`**
  - Actualizar producto existente por ID. Request: `ProductoRequest` → Response: `ProductoResponse`

- **PATCH `/api/productos/{id}/desactivar`**
  - Desactivar (baja lógica) producto por ID. Response: `ProductoResponse`

## ⚙️ Decisiones tomadas y convenciones

- Se siguió diseño en capas y no se expuso la entidad dominio en ninguna respuesta.
- Mapping entre `Producto` y DTO es manual y centralizado.
- Validaciones declarativas en DTO (JSR 380).
- Baja lógica sobre campo `activo` (no se elimina físicamente).
- Excepciones de negocio y recurso no encontrado reutilizan el handler global preexistente.
