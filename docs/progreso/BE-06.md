## Decisiones tomadas
- Se siguió el patrón exacto de BE-05 (Productos), con arquitectura en capas, validación en DTOs, mapeo manual, y manejo de excepciones centralizadas.
- Los contactos de cada repartidor se incluyen en la response como lista de objetos DTO anidados.
- No se incluyen métodos extra de búsqueda ni lógica adicional, solo lo definido en el ticket y requerimientos.

## Dependencias generadas
- El frontend puede consumir /api/repartidores para ABM de repartidores y selección en carga de pedidos.
- Base para cualquier lógica futura relacionada a entregas, asignación de pedidos, etc.
